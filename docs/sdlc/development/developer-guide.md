<!-- sdlc:auto:start overview -->
UAT-Feedback is a two-application monorepo generated by the Quorq AI SDLC platform for the 'Diagnostic Odyssey Copilot — axSpA Proof of Concept'. `frontend/` is a Vite + React 19 single-page app (React Router, TanStack Query, Tailwind v4) whose screens — Sign in, Set password, Start, Worklist, Case summary, Insufficient history, My health, Timeline, Admin — are wired to a shared `src/lib/api.ts` fetch client that sends an opaque bearer token. `backend/` is a FastAPI 0.115 service on SQLAlchemy 2 with Alembic migrations, exposing `/health` plus `/api/auth/*`, `/api/worklist`, `/api/cases/*`, `/api/patients/me/*`, `/api/demo/personas/*`, `/api/invites/*` and `/api/admin/*` routes. The backend layers a condition pack (`app/pack/`, YAML-backed), a scoring engine (`app/engine/`), guardrails (`app/guardrails/`), dataset ingest (`app/ingest/`) and an RQ worker (`app/worker.py`) over a PostgreSQL 16 database, with Redis for cache and queue, S3 or local disk for files, Anthropic for clue extraction and SendGrid for mail. Every backing service has a working local default: with nothing configured the app falls back to a local SQLite file and reports cache/queue as unavailable.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js 20+ and npm (Vite 6, React 19, TypeScript 5.9)
- Python 3.12 (the backend image is python:3.12-slim)
- Docker / Docker Compose (optional, for the PostgreSQL 16 and Redis 7 services in docker-compose.yml)
- A native Pango stack (libpango-1.0-0) if you need WeasyPrint PDF rendering outside Docker; otherwise the PDF code must be mocked
- Chromium for Playwright, installed via `npm run test:e2e:install`
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository and copy the sample environment file: `cp .env.example .env` (see ENVIRONMENT.md and backend/README.md for what each variable holds; every variable has a working local default).
2. Optional — start the backing services: `docker compose up -d db` (and a Redis service; note both `redis` and `redis-queue` in docker-compose.yml publish port 6379, so start only one unless you remap a port).
3. Create the backend virtualenv: `cd backend && python3.12 -m venv .venv`
4. Install backend dependencies: `.venv/bin/pip install -r requirements.txt`
5. Apply the schema (only needed when DATABASE_URL points at PostgreSQL; the default is a local SQLite file): `.venv/bin/alembic upgrade head`
6. Run the API: `.venv/bin/python -m uvicorn app.main:app --reload` and check `http://localhost:8000/health`
7. In a second shell install the frontend: `cd frontend && npm install`
8. Run the SPA: `npm run dev` (it calls `VITE_API_BASE_URL`, defaulting to `http://localhost:8000`)
9. If you need seeded accounts, set BOOTSTRAP_ADMIN_EMAIL / BOOTSTRAP_ADMIN_PASSWORD (and SMOKE_TEST_EMAIL / SMOKE_TEST_PASSWORD) to values of your own, e.g. BOOTSTRAP_ADMIN_PASSWORD=<set-at-first-login>, before starting the API; unset, nothing is seeded.

<!-- sdlc:auto:start conventions -->
- One router module per architecture component, each with a URL prefix and tags; routes return plain dicts typed as dict[str, Any].
- Authentication is an opaque bearer token returned in the login response body — never a cookie; a global HTTP middleware rejects unauthenticated requests outside the open paths, and route dependencies (require_api_access, require_admin, require_staff, CurrentUser) decide the rest.
- The schema changes only via Alembic migrations; `users` and `sessions` are the two exceptions created by Base.metadata.create_all at startup, so nothing else may carry a foreign key to them.
- Models use SQLAlchemy 2 `Mapped[...]` / `mapped_column`, string UUID primary keys with a `_uuid()` default, and `JSONB_OR_JSON` so JSON columns become JSONB on PostgreSQL.
- Every configuration value is read through app/config.py at call time with a local default; credential values are never logged or returned (statuses are reported as 'connected' / 'not-configured', values as 'not-shown').
- Read payloads are wrapped with `with_notice(...)` so the synthetic-data notice travels with every response, and PDF exports repeat it per page.
- Clinical constants live in the condition pack configuration, not in code — routers and the engine only move pack data around.
- Frontend imports use the `@/` alias for `src/`; screens live one module per route in `src/screens/` and are registered in the exported `ROUTES` table in App.tsx.
- All HTTP calls go through `apiFetch` in `src/lib/api.ts`, which attaches the bearer, normalises error `detail` into `ApiError`, and dispatches SESSION_EXPIRED_EVENT on a 401 from an authenticated call.
- Tests sit beside what they cover on the frontend (`*.test.tsx`) and under `tests/unit` / `tests/integration` on the backend; Playwright specs stay in `e2e/` and are excluded from the Vitest include pattern.
- Python is linted and formatted with Ruff; TypeScript with ESLint plus Prettier.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Every API call returns 401 {"detail":"Not authenticated"}. | The global middleware in app/main.py requires a bearer on all but the open paths. Sign in via POST /api/auth/login and send `Authorization: Bearer <token>`, or set SECRET_KEY on the API and the matching VITE_API_SECRET_KEY for the frontend build. |
| The browser blocks SPA requests to the API with a CORS error. | Set ALLOWED_ORIGINS on the backend to the SPA's origin (comma separated). It defaults to the Vite dev server only. |
| `docker compose up -d` fails with a port conflict on 6379. | docker-compose.yml defines both `redis` and `redis-queue` publishing 6379. Start only one (`docker compose up -d db redis`) or remap one service's host port. |
| `pytest` cannot `import app`. | Run it from the backend/ directory so pytest.ini's `pythonpath = .` applies: `cd backend && .venv/bin/python -m pytest`. |
| Importing or running the PDF code fails on missing native libraries. | WeasyPrint needs the Pango stack. The Dockerfile installs libpango-1.0-0; locally either install it or mock the renderer, as the unit tests do. |
| `npm run build` succeeds but deployment or `tsc` fails. | `vite build` does not typecheck. Run `npm run typecheck` and fix the reported errors (commonly untyped `useState({})` later read for named fields). |
| /health reports cache or queue unavailable, or POST /api/admin/jobs returns 503. | Set REDIS_URL to a running Redis 7 instance and start the worker with `.venv/bin/python -m app.worker`; without Redis the queue is intentionally reported unavailable. |
| POST /api/admin/ingest-runs returns 422. | Supply dataset_version and source_uri in the body, or configure INGEST_DATASET_VERSION and INGEST_SOURCE_URI in the environment. |
| A new ingest run returns 409 'already in progress' after a crashed job. | The router treats a run as live while the queue backs it, and otherwise after a 30-minute stale window. Restart Redis/the worker so the queue can be read, or wait out the stale window. |
| Sign-in works but no accounts exist. | Bootstrap seeding only runs when BOOTSTRAP_ADMIN_EMAIL/BOOTSTRAP_ADMIN_PASSWORD (and optionally SMOKE_TEST_EMAIL/SMOKE_TEST_PASSWORD) are set; choose your own values such as <set-at-first-login> and restart the API. An empty users table is the correct local state. |
| Playwright e2e runs fail to start the API. | playwright.config.ts launches `backend/.venv/bin/python -m uvicorn`, so the backend virtualenv must exist with requirements installed before the run, or set E2E_BASE_URL to a deployed app. |
<!-- sdlc:auto:end troubleshooting -->
