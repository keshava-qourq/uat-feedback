<!-- sdlc:auto:start overview -->
UAT-Feedback is a two-application monorepo generated by the Quorq AI SDLC platform for the 'Diagnostic Odyssey Copilot — axSpA Proof of Concept' PRD. `frontend/` is a Vite + React 19 single-page app (React Router 7, Tailwind CSS 4, TypeScript) whose screens were generated from an approved design and currently render seeded sample data rather than calling the API; `frontend/src/lib/api.ts` is the prepared seam (apiFetch, bearer-token handling, VITE_API_BASE_URL) for wiring screens to real endpoints. `backend/` is a FastAPI 0.115 service scaffold with SQLAlchemy 2 and Pydantic 2: it currently exposes only `GET /health`, declares no models, and creates tables from the models on startup (no migrations). The database defaults to a local SQLite file and can be pointed at Postgres via `DATABASE_URL`; `docker-compose.yml` provides PostgreSQL 16 and Redis 7 containers, and `.github/workflows/deploy.yml` builds the backend image and publishes the frontend bundle to AWS Amplify on pushes to `main`.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->

- npm
- Python 3.12 (matching the backend Dockerfile base image)
- pip (and optionally venv for an isolated environment)
- Docker + Docker Compose (only if you want the PostgreSQL/Redis services from docker-compose.yml)

<!-- sdlc:auto:start setup -->
1. Clone the repository and open it in your editor (a .devcontainer/devcontainer.json is included if you prefer a dev container).
2. Backend: cd backend
3. Create and activate a virtual environment: python -m venv .venv && source .venv/bin/activate
4. Install backend dependencies: pip install -r requirements.txt
5. Start the API: uvicorn app.main:app --reload  (serves http://localhost:8000, docs at /docs, health at /health). It uses SQLite at ./app.db unless DATABASE_URL is set.
6. Frontend: in a second terminal, cd frontend
7. Install frontend dependencies: npm install
8. Start the dev server: npm run dev  (Vite serves http://localhost:5173, which the backend already allows via CORS)
9. Optional — start PostgreSQL 16 and Redis 7 locally: docker compose up -d db redis
10. Optional — point the backend at Postgres instead of SQLite by exporting DATABASE_URL (user/password/db are defined in docker-compose.yml; use your own values, e.g. postgresql+psycopg://<db-user>:<db-password>@localhost:5432/<db-name>).
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Monorepo split: frontend/ (SPA) and backend/ (API) each own their own tooling, ignore files and dependency manifests.
- Frontend imports use the `@/` alias for src/, configured in both vite.config.ts and tsconfig.json.
- Screens live one-per-file in src/screens/ and are registered in the route table in src/App.tsx; shared UI, icons and brand tokens live in src/lib/.
- Branding is expressed as CSS custom properties (var(--brand-*)) applied through Tailwind utility classes.
- Component tests sit beside the component they cover and are matched only under src/ (Vitest), while *.spec.ts under e2e/ belongs to Playwright.
- Backend layering: database.py owns the engine/session, models.py the SQLAlchemy models, schemas.py the Pydantic request/response models, routers/ one module per component that owns endpoints.
- Request-scoped DB sessions are provided by the get_db dependency; tables are created in the FastAPI lifespan, not at import time, so importing the app opens no connection.
- Configuration comes from environment variables with safe local defaults: DATABASE_URL (defaults to SQLite), ALLOWED_ORIGINS (defaults to the Vite dev origins), VITE_API_BASE_URL and VITE_API_SECRET_KEY on the frontend.
- Unimplemented endpoints are expected to return the typed StubResponse placeholder rather than raising, keeping the OpenAPI document complete.
- Python is linted and formatted with Ruff; TypeScript with ESLint and Prettier.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `npm run build` succeeds but deployment or `tsc` fails. | vite build does not typecheck. Run `cd frontend && npm run typecheck` and fix the reported errors (commonly an untyped useState({}) later read for named fields). |
| Browser calls from the SPA are blocked by CORS. | The backend allows http://localhost:5173 and http://127.0.0.1:5173 by default. For any other origin, set ALLOWED_ORIGINS to a comma-separated list before starting uvicorn. |
| `pytest` fails with ModuleNotFoundError: No module named 'app'. | Run pytest from the backend/ directory so pytest.ini (pythonpath = .) applies, with the virtualenv activated. |
| The backend cannot connect to the database on startup. | Unset DATABASE_URL to fall back to the bundled SQLite file, or start the Postgres container with `docker compose up -d db` and point DATABASE_URL at it using your own credentials. |
| `docker compose up` fails with a port conflict on 6379. | docker-compose.yml maps both the `redis` and `redis-queue` services to host port 6379. Start only one of them (e.g. `docker compose up -d db redis`) or change one of the host port mappings. |
| Playwright fails to start because backend/.venv is missing. | The webServer config launches `../backend/.venv/bin/python`. Create it first: `cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt`, or set E2E_BASE_URL to run against a deployed URL instead. |
| Chromium crashes during Playwright runs in a container. | The config already passes --disable-dev-shm-usage; if it still crashes, increase the container's /dev/shm size or lower parallelism (workers is already 1). |
| The deployed frontend calls http://localhost:8000. | VITE_API_BASE_URL is inlined at build time. Rebuild with VITE_API_BASE_URL set to the real API URL (the deploy workflow sets it for CI builds); keep any secret values out of source control and supply them as <your-api-key> style secrets. |
<!-- sdlc:auto:end troubleshooting -->
