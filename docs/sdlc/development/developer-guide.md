<!-- sdlc:auto:start overview -->
UAT-Feedback is a two-application monorepo generated by the Quorq AI SDLC platform for the "Diagnostic Odyssey Copilot" axSpA proof of concept. `frontend/` is a Vite + React 19 single-page app (TypeScript, Tailwind 4, React Router 7, TanStack Query) whose screens were generated from an approved design and still largely run on seeded sample data; `frontend/src/lib/api.ts` is the single HTTP client, sending an `Authorization: Bearer` header built from a stored session token or the shared build-time key. `backend/` is a FastAPI 0.115 service on SQLAlchemy 2 with Alembic migrations, structured as one router per architecture component (`auth`, `data`, `ingest_runs`, `admin`, `pack`, `invites`) plus an unauthenticated `GET /health`. It defaults to a local SQLite file when `DATABASE_URL` is unset, reports Redis cache/queue availability rather than requiring them, and keeps condition-specific clinical logic out of code in declarative "condition packs" (`app/pack/packs/*.yaml`). Background work (ingest runs, dedup check) is queued to RQ on Redis and executed by `python -m app.worker`. Docker Compose provides PostgreSQL 16 and Redis 7 locally, and a GitHub Actions workflow builds the backend image and publishes the frontend bundle.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js 20+ with npm (Vite 6 / React 19 toolchain)
- Python 3.12 (the backend image is built on python:3.12-slim)
- Docker and Docker Compose (optional, for the PostgreSQL 16 and Redis 7 services in docker-compose.yml)
- Native Pango libraries (libpango-1.0-0) if you want WeasyPrint PDF rendering to run outside Docker
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository and copy the example environment file: `cp .env.example .env` (every backend variable has a working local default, so none is required to start).
2. Backend: `cd backend && python -m venv .venv && .venv/bin/python -m pip install -r requirements.txt`
3. Optional backing services: from the repository root run `docker compose up -d db redis` and point `DATABASE_URL` / `REDIS_URL` at them; without them the backend falls back to a local SQLite file (`./app.db`) and reports cache and queue as unavailable.
4. Apply migrations when using a real database: `cd backend && .venv/bin/alembic upgrade head` (the `users` and `sessions` tables are still created by `Base.metadata.create_all` at startup).
5. Start the API: `cd backend && .venv/bin/python -m uvicorn app.main:app --reload` and check `http://localhost:8000/health`.
6. Frontend: `cd frontend && npm install`
7. Start the SPA: `cd frontend && npm run dev` (it calls `http://localhost:8000` unless `VITE_API_BASE_URL` is set).
8. Optional: set `BOOTSTRAP_ADMIN_EMAIL` / `BOOTSTRAP_ADMIN_PASSWORD` (and `SMOKE_TEST_EMAIL` / `SMOKE_TEST_PASSWORD`) to <admin-email> and <bootstrap-admin-password> values of your own before starting the API if you want seeded accounts; leave them unset and no account is seeded.

<!-- sdlc:auto:start conventions -->
- Backend layering: one router per architecture component under app/routers/, business logic in sibling modules (invites.py, passwords.py, dedup.py, evaluation.py), SQLAlchemy models in app/models.py and Pydantic bodies declared next to the routes that use them.
- Schema changes go through Alembic only; the sole exception is `users` and `sessions`, created by `Base.metadata.create_all` at startup, so no migration-owned table may carry a foreign key to them.
- Settings are read from the environment at call time through app/config.py, each with a working local default; no credential value is ever logged, returned or committed (admin settings report only `connected` / `not-configured` and a masked value).
- Auth is an opaque bearer session returned in the response body, never a cookie; a middleware in main.py refuses unauthenticated requests and the route dependency decides between the shared API key and a live session. `allow_credentials` is False in CORS.
- Every read payload is wrapped by `with_notice(...)` and every PDF page carries the synthetic-data notice; the SPA mounts SyntheticDataNotice once in the root layout so no screen hand-adds it.
- Routes are deliberately thin and page-less, returning items oldest-first, with evaluation-cutoff filtering applied on read.
- Condition-specific clinical constants live in YAML condition packs, resolved through app/pack; code never names a condition, code list or threshold.
- Frontend: all HTTP goes through `apiFetch` in src/lib/api.ts, which attaches the bearer and raises `ApiError`; a 401 on an authenticated call clears the token and dispatches SESSION_EXPIRED_EVENT, which App.tsx turns into a redirect.
- Frontend imports use the `@/` alias for `src/`; routes are declared once in the exported `ROUTES` table in App.tsx; component tests live beside the components they cover.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` cannot `import app`. | Run pytest from the `backend/` directory so pytest.ini's `pythonpath = .` applies: `cd backend && .venv/bin/python -m pytest`. |
| `/health` reports cache and queue unavailable, and queueing a job returns 503. | That is the expected state with no Redis. Start it with `docker compose up -d redis` and set `REDIS_URL` to your local instance before starting the API and `python -m app.worker`. |
| Browser calls from the SPA are blocked by CORS. | Set `ALLOWED_ORIGINS` on the backend to the SPA's origin (comma separated); it defaults to the Vite dev server origin. Only `Authorization` and `Content-Type` headers are allowed. |
| The SPA calls localhost in a deployed build. | `VITE_API_BASE_URL` is inlined at build time; set it (and `VITE_API_SECRET_KEY` to <api-secret-key>) before `npm run build`, otherwise api.ts falls back to http://localhost:8000. |
| `npm run build` succeeds but deployment fails on types. | `vite build` does not typecheck. Run `npm run typecheck` (`tsc --noEmit`) and fix the reported errors, typically untyped `useState({})` later read for named fields. |
| Starting an ingest run returns 409 "already in progress" although nothing is running. | One run at a time is enforced; a row left behind by an interrupted process is closed off once the queue shows no backing job, or after the 30-minute stale window. Bring the worker and Redis up so the queue can be read. |
| Importing or running anything that renders PDFs fails on a missing native library. | WeasyPrint needs the Pango stack; the Dockerfile installs `libpango-1.0-0`. Install it locally or mock the renderer, as the unit tests do. |
| Playwright specs are collected by Vitest, or Chromium crashes in a container. | Vitest is scoped to `src/` so `e2e/` is left to Playwright; run the suites with their own commands. Chromium already launches with `--disable-dev-shm-usage` via playwright.config.ts for small /dev/shm containers. |
| Signing in fails because no account exists. | An empty `users` table is correct locally. Set `BOOTSTRAP_ADMIN_EMAIL` to <admin-email> and `BOOTSTRAP_ADMIN_PASSWORD` to <bootstrap-admin-password> before startup; seeding is idempotent and leaves an existing account untouched. |
<!-- sdlc:auto:end troubleshooting -->
