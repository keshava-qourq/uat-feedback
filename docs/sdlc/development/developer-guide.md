<!-- sdlc:auto:start overview -->
UAT-Feedback is a two-application monorepo generated by the Quorq AI SDLC platform for the "Diagnostic Odyssey Copilot — axSpA Proof of Concept" PRD. `frontend/` is a Vite + React 19 single-page app (React Router 7, TanStack Query, Tailwind 4, Recharts) whose approved screens currently render seeded sample data; `frontend/src/lib/api.ts` is the prepared seam for calling the real API. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2 ORM models, Alembic migrations, and Pydantic 2 schemas. It defaults to a local SQLite database (`sqlite:///./app.db`) so a fresh clone runs with no database server, but `DATABASE_URL` can point at the PostgreSQL 16 container in `docker-compose.yml`. The API exposes an unauthenticated `/health` probe plus authenticated routers for auth/sessions, worklist and patient timeline reads, PDF exports (WeasyPrint), demo personas, admin settings, and admin ingest runs backed by an RQ/Redis job queue. A global HTTP middleware rejects any request without a bearer token except the open routes.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js 20+ and npm (Vite 6, TypeScript 5.9)
- Python 3.12 (the backend Dockerfile builds on python:3.12-slim)
- pip and a virtual environment tool (venv)
- Docker and Docker Compose (optional — only for the PostgreSQL 16 and Redis 7 containers in docker-compose.yml)
- System library libpango-1.0-0 if you render the PDF exports locally with WeasyPrint (installed in the Dockerfile)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository and copy the example environment file: `cp .env.example .env`
2. Create and activate a backend virtual environment: `cd backend && python3.12 -m venv .venv && source .venv/bin/activate`
3. Install backend dependencies: `pip install -r requirements.txt`
4. (Optional) Start PostgreSQL and Redis: `docker compose up -d` from the repository root, then export `DATABASE_URL` pointing at that server with your own credentials, e.g. `export DATABASE_URL=postgresql+psycopg://<db-user>:<db-password>@localhost:5432/app`. Without this the backend uses SQLite at `backend/app.db`.
5. Run the API: `uvicorn app.main:app --reload` from `backend/` (tables are created from the models at startup; OpenAPI docs are at http://localhost:8000/docs)
6. In a second terminal install frontend dependencies: `cd frontend && npm install`
7. Start the SPA: `npm run dev` (http://localhost:5173, which is already in the backend's default CORS allow-list)
8. If you call the API from the SPA, set `VITE_API_BASE_URL` and `VITE_API_SECRET_KEY` in `frontend/.env` using your own values (e.g. `VITE_API_BASE_URL=http://localhost:8000` and `VITE_API_SECRET_KEY=<your-api-secret-key>`, matching the backend's `API_SECRET_KEY`)

<!-- sdlc:auto:start conventions -->
- Backend: one router module per architecture component, mounted in `main.py`; route prefixes are `/api/...` with `/health` left open and unauthenticated.
- Authentication: a global HTTP middleware requires a bearer token on every non-open route; route dependencies (`require_api_access`, `CurrentUser`, `require_staff`) decide whether it is the shared `API_SECRET_KEY` or a live session token.
- Database access: one SQLAlchemy session per request via the `get_db` dependency, typed as `Annotated[Session, Depends(get_db)]`.
- Models use SQLAlchemy 2 declarative style (`Mapped[...]` / `mapped_column`) on a shared `Base`, string UUID primary keys, and explicit composite indexes on `(patient_id, time)`.
- Credentials are never returned: admin settings report only `connected` / `not-configured` with the value masked as `not-shown`.
- Every read payload carries the synthetic-data notice via `with_notice(...)`, and every PDF page repeats it; the frontend mounts `SyntheticDataNotice` once in the root layout so new routes inherit it.
- Frontend imports use the `@/` alias for `src/`; component tests live beside the component they cover (`*.test.tsx`), while Playwright specs live in `e2e/`.
- Backend style and lint are enforced by Ruff (`ruff.toml`); frontend by ESLint flat config plus Prettier.
- Routes are declared in a single exported `ROUTES` table in `App.tsx` so guardrail tests can iterate them.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Every API call returns 401 `Not authenticated`. | All routes except `/health` require an `Authorization: Bearer ...` header. Send either the shared `API_SECRET_KEY` the backend is configured with, or a session token obtained from `POST /api/auth/login` and stored via `setSessionToken` in `frontend/src/lib/api.ts`. |
| The browser blocks SPA requests to the API with a CORS error. | The backend allows `http://localhost:5173` and `http://127.0.0.1:5173` by default. If the SPA runs on another origin, set `ALLOWED_ORIGINS` (comma separated) in the backend environment. |
| `pytest` fails with `ModuleNotFoundError: No module named 'app'`. | Run pytest from the `backend/` directory, where `pytest.ini` sets `pythonpath = .`. |
| `npm run build` succeeds but deployment or `tsc` fails. | `vite build` does not typecheck. Run `npm run typecheck` and fix the reported errors (commonly untyped `useState({})` reads). |
| `npm run test:e2e` cannot start the backend web server. | The Playwright config launches `../backend/.venv/bin/python -m uvicorn app.main:app`. Create that virtualenv at `backend/.venv` and install `requirements.txt` into it, or set `E2E_BASE_URL` to run against an already deployed URL. |
| `docker compose up` fails with a port conflict on 6379. | The `redis` and `redis-queue` services both publish 6379. Start only one of them (e.g. `docker compose up -d db redis-queue`) or change one published port. |
| `POST /api/admin/ingest-runs` returns 422. | Supply `dataset_version` and `source_uri` in the request body, or set `INGEST_DATASET_VERSION` and `INGEST_SOURCE_URI` in the backend environment. |
| `POST /api/admin/ingest-runs` returns 409 or 503. | 409 means a run is already `queued` or `running` — wait for it to finish (only one run at a time is allowed). 503 means the RQ/Redis queue is unreachable; start the Redis container and check the queue configuration. |
| PDF export endpoints fail locally with a WeasyPrint/Pango error. | Install the Pango system library (`libpango-1.0-0` on Debian/Ubuntu, as the Dockerfile does) before calling the `.pdf` routes. |
| Admin settings reports the database or LLM as `not-configured`. | Set `DATABASE_URL` to a reachable database and provide `ANTHROPIC_API_KEY` (or `LLM_API_KEY`) as `<your-api-key>` in the backend environment; the endpoint only reports status and never echoes values. |
